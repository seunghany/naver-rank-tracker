# 콘텐츠 자동화 파이프라인

블로그 글감 발굴 → 초안 작성 → 품질 검사 → 네이버 발행까지.
추적기(`src/track.py`)와 같은 저장소에 있지만 독립적으로 동작한다.

```
M1 find_topics.py   상위 30개 글의 제목·요약 수집 → 빈 각도 탐지
      ↓ content/briefs/<날짜>-<키워드>.json
M2 write_draft.py   빈 각도 + 사실 바구니 → LLM 초안
      ↓ content/drafts/<날짜>-<키워드>.md
M3 quality_gate.py  8개 항목 기계 검사 (실패 시 발행 차단)
      ↓
M4 publish_naver.py Playwright 로 스마트에디터 발행
      ↓ content/published/
```

---

## 먼저 읽을 것 — 이 자동화의 실제 리스크

네이버는 **2020년 5월 6일 블로그 글쓰기 API 를 종료**했다. 네이버가 밝힌 이유는
"광고성 블로그 퇴출"이었다. 즉 자동 포스팅은 기술적 한계가 아니라 **정책적으로
막아둔 것**이고, M4 가 쓰는 브라우저 자동화는 그 우회 경로다.

2026년 보도 기준 네이버가 제재를 강화한다고 명시한 항목에 **"매크로 자동화"**가
포함돼 있다. 적발 시 영향 범위는 블로그 하나가 아니다 — 리뷰 어뷰징 제재 사례에서
확인된 대로 AI 브리핑 노출이 영구 삭제되고 동일 명의 계정 전체가 묶인다.

그래서 이 저장소는 M1~M3 에 무게를 두고, M4 는 **기본값이 임시저장**이다.
실제 발행을 켜려면 설정 파일과 명령줄 양쪽에서 각각 한 번씩 풀어야 한다.

### 구현하지 않은 것

공감·댓글·서이추·이웃추가 자동화. 이건 계정 정지 사유가 명확한 영역이라
요청이 있어도 넣지 않는다.

## 셋업

### 1. 의존성

```bash
pip install -r requirements.txt
playwright install chromium        # M4 를 쓸 때만
```

### 2. 키

| 환경변수 | 어디서 | 필요한 단계 |
|---|---|---|
| `NCP_API_KEY_ID` / `NCP_API_KEY` | NAVER API HUB | M1 |
| `ANTHROPIC_API_KEY` | console.anthropic.com | M2 |

M4 는 API 키를 쓰지 않는다. 대신 로그인 세션을 재사용한다.

### 3. 네이버 로그인 (1회)

```bash
python src/naver_login.py
```

브라우저가 열리면 **직접** 로그인한다. 비밀번호는 스크립트도 저장소도 다루지
않는다. 세션은 `.naver-profile/` 에 남고, 이 폴더는 `.gitignore` 에 있다.

> **중요**: 이 저장소는 Public 이다. `.naver-profile/` 이 커밋되면 세션 쿠키가
> 전 세계에 공개된다. `git status` 에 이 폴더가 보이면 커밋하지 말 것.

### 4. 사실 바구니 채우기

`content/facts/reboot.yml`, `content/facts/teampoise.yml`

여기 적힌 숫자·사례만 글에 들어간다. LLM 이 수치를 지어내지 못하도록 프롬프트에서
막고, 품질 게이트가 인용 개수를 세서 이중으로 확인한다.

**최소 5개는 채우고 시작하는 것을 권한다.** 1차 데이터가 없는 글은 상위 노출이
안 되는 게 아니라, 애초에 쓸 이유가 없다.

## 실행

```bash
# 한 번에
python src/pipeline.py 철산하이록스 Reboot

# 단계별
python src/find_topics.py 철산하이록스
python src/write_draft.py content/briefs/2026-09-20-철산하이록스.json Reboot
python src/quality_gate.py content/drafts/2026-09-20-철산하이록스.md
python src/publish_naver.py content/drafts/2026-09-20-철산하이록스.md          # 임시저장
python src/publish_naver.py content/drafts/2026-09-20-철산하이록스.md --live   # 실제 발행
```

`--live` 는 `config/content.yml` 의 `publish.dry_run: false` 와 **둘 다** 맞아야
동작한다.

---

## 설계상 일부러 하지 않은 것

**상위글 본문을 긁어오지 않는다.** M1 은 네이버 검색 API 가 주는 제목·요약만
쓴다. 본문을 긁어 LLM 에 넣고 다시 쓰게 하면 그게 정확히 유사문서 필터가 잡는
패턴이다. "인기 글을 크롤링해서 비슷하게 쓴다"는 접근은 가장 빠른 저품질 경로다.

대신 M1 은 **"상위 30개가 공통으로 안 다룬 각도"**를 찾는다. 노리는 건 1등 글의
재탕이 아니라 아무도 제대로 답하지 않은 질문이다. 2026년 AI 브리핑 인용의 49.3%
가 Top10 밖에서 나온다는 조사가 이 방향의 근거다.

## 품질 게이트가 보는 8가지

| 항목 | 기준 | 왜 |
|---|---|---|
| 길이 | 1,200~6,000자 | 얄팍한 글은 체류시간이 안 나온다 |
| 소제목 | 3개 이상 | AI 브리핑이 구간을 뽑아가야 한다 |
| 표·목록 | 최소 1개 | 정보 추출성 |
| 사실 인용 | 2개 이상 | 1차 데이터 없는 글은 일반론이다 |
| 첫 문단 | 인사말 금지 | 직답이 먼저 와야 체류시간이 산다 |
| 상투어 | 9개 금칙어 | AI 티가 나면 원본성 점수가 깎인다 |
| 키워드 밀도 | 2% 이하 | 쑤셔넣기는 2026년엔 역효과 |
| 자기 유사도 | 자카드 0.35 이하 | 내 글끼리 겹치면 중복 판정 |

기준은 `config/content.yml` 에서 조정한다.

---

## M4 가 실패할 때

스마트에디터 DOM 은 자주 바뀐다. 셀렉터가 깨지면 스크립트가
`content/state/debug-*.png` 에 스크린샷을 남긴다. 그 파일을 Claude 에게 보내면
`src/publish_naver.py` 상단의 `SEL` 딕셔너리를 고칠 수 있다.

M1~M3 은 이 문제와 무관하게 계속 동작한다.

---

## 추적기와의 연결

발행한 글이 실제로 순위에 잡히는지는 기존 추적기가 매일 09:00 에 확인한다.
`data/rankings.csv` 의 `blog` 행이 그 답이다. 2~3주 뒤에도 순위 진입이 0이면
자동화를 늘릴 게 아니라 키워드 선택을 다시 해야 한다는 신호다.
